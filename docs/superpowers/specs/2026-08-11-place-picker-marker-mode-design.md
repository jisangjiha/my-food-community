# 고른 장소를 지도에 못 박기 (마커 모드)

작성일: 2026-08-11

## 배경

장소 선택 화면(`/register/place`)은 핀이 화면 중앙에 고정되고 지도가 그 밑에서
흐르는 방식이다. 그래서 지도의 모든 움직임이 "위치를 옮겼다"로 읽힌다.

이 규칙이 실제 사용에서 깨졌다. 사용자가 "스타벅스 굽은다리점"을 검색해 고른 뒤
**그 건물이 맞는지 확인하려고 지도를 확대하거나 둘러보면 선택이 풀린다.** 확인하려는
행동이 확인 대상을 없애 버린다.

확대·축소는 앞선 수정(`a38ddd1`)에서 중심을 되돌려 해결했다. 이 문서는 남은 절반 —
**지도를 이동해도 고른 장소가 유지되게** 만든다.

## 범위

**한다**

- `NaverMap`에 `variant="marker"` 추가: 좌표에 마커를 고정하고 지도는 자유롭게 움직인다
- 상호명이 있으면 마커 모드, 없으면 지금의 핀 모드
- 마커 모드에서 "지도에서 직접 선택"으로 핀 모드로 전환
- 줌 중심 고정은 핀 모드에만 적용

**하지 않는다**

- 마커가 화면 밖으로 나갔을 때 "선택한 위치로 돌아가기". 없어도 막히지 않고
  화면에 요소가 하나 더 붙는다.
- 마커를 직접 끌어 옮기기(draggable marker). 핀 모드가 이미 그 일을 한다.
- 상세 화면 변경.

## 결정과 근거

### 1. 모드는 상호명 유무로 갈린다

새 상태값을 만들지 않는다. `name`이 이미 "검색으로 고른 장소인가"를 뜻한다.

```
name !== ""  →  marker  (좌표에 고정. 지도를 움직여도 불변)
name === ""  →  picker  (중앙 핀. 멈출 때마다 주소 갱신)
```

별도 `mode` 상태를 두면 `mode === "marker"`인데 `name`이 빈 조합이 가능해지고,
둘을 동기화하는 코드가 생긴다. 파생시키면 어긋날 수 없다.

### 2. 마커 모드에서는 지도가 아무것도 보고하지 않는다

`onCenterChange`를 넘기지 않는다. 리스너 자체를 달지 않으므로 리버스 지오코딩
요청도 나가지 않는다. 지도를 어디로 끌든 `address`·`lat`·`lng`는 그대로다.

이것이 요구사항의 핵심이다 — "지도에 딱 고정이 되고 확대축소해도 선택된 음식점이
바뀌면 안 된다".

### 3. 전환 버튼은 지도가 아니라 카드 안에 둔다

"지도에서 직접 선택"은 선택한 위치 카드 안, 주소 아래에 놓는다. 지도 위에 얹으면
타일을 가리고, 시안의 지도 면에는 컨트롤이 없다.

누르면 `name`을 비운다. 그 한 줄로 모드가 바뀐다(1번 규칙).

**지도는 움직이지 않는다.** 검색 직후라면 마커가 화면 중앙에 있으므로, 전환 즉시
핀이 정확히 그 자리에서 시작한다. 거기서 조금씩 끌어 미세조정하는 것이 자연스럽다.
전환 시 주소를 다시 조회하지 않는 이유도 같다 — 좌표가 그대로라 답이 같다.

### 4. 줌 중심 고정은 핀 모드에만

`zoom_changed`에서 중심을 되돌리는 보정은 "중앙 핀이 곧 내 위치"라서 필요했다.
마커 모드는 중심에 아무 의미가 없으므로 걸지 않는다. 커서 쪽으로 확대되는 네이버
기본 동작이 그대로 살아 있는 편이 둘러보기에 낫다.

구현상 이것은 자연스럽게 갈린다 — 두 리스너 모두 `variant === "picker"`일 때만 단다.

### 5. `variant`를 셋으로 늘린다

지금 `picker | static`이 세 가지 성질(마커·중앙 핀·조작 가능)을 두 이름에 뭉쳐 놓고
있다. 마커 모드는 그 사이 조합이다.

| variant | 마커 | 중앙 핀 | 드래그·줌 | 중심 보고 | 줌 중심 고정 |
| --- | --- | --- | --- | --- | --- |
| `picker` | — | ✓ | ✓ | ✓ | ✓ |
| `marker` | ✓ | — | ✓ | — | — |
| `static` | ✓ | — | — | — | — |

`marker`와 `static`은 조작 가능 여부만 다르고, `picker`와 `marker`는 조작 가능한
점만 같다. 셋을 각각 이름 지어 두면 호출부가 조합을 조립할 필요가 없다.

## 아키텍처

```
PlaceLocationPicker
  ├─ name !== "" ─→ NaverMap variant="marker" center={선택 좌표}
  │                   (지도 자유, 선택 불변, 요청 없음)
  │                 Card: 상호명 + 주소 + [지도에서 직접 선택] → setName("")
  │
  └─ name === "" ─→ NaverMap variant="picker" onCenterChange={…}
                      (중앙 핀, idle마다 주소 갱신, 줌 중심 고정)
                    Card: "장소를 선택해 주세요" + 주소
```

| 파일 | 상태 | 역할 |
| --- | --- | --- |
| `src/components/ui/NaverMap.tsx` | 수정 | `variant="marker"`, 리스너를 picker에만 |
| `src/components/places/PlaceLocationPicker.tsx` | 수정 | 모드 분기 + 전환 버튼 |
| `src/stories/ui/Handoff.stories.tsx` | 수정 | `marker` 변형 스토리 |

## 에러 처리

새로 생기는 실패 경로가 없다. 마커 모드는 네트워크를 쓰지 않는다.

키가 없거나 인증이 실패하면 지금처럼 `MapCanvas` 도식으로 폴백한다. 도식에는 마커가
없고 중앙 핀만 있는데, 그건 폴백이 `variant`를 모르기 때문이고 "지도를 못 그렸다"는
사실이 더 중요하므로 그대로 둔다.

## 검증

1. 타입·린트 통과
2. 검색으로 "예빈당 성수본점" 선택 → 마커가 보이고 중앙 핀이 없다
3. 지도를 크게 드래그 → 상호명·주소가 **그대로**, `/api/geocode` 요청 **0건**
4. 확대·축소 → 마찬가지로 그대로. 커서 쪽으로 확대된다(중심 고정 없음)
5. "지도에서 직접 선택" → 중앙 핀이 나타나고 상호명이 "장소를 선택해 주세요"로,
   주소는 그대로(좌표가 안 바뀌었으므로)
6. 그 상태로 드래그 → 주소가 갱신된다(핀 모드 동작)
7. 그 상태로 확대·축소 → 주소가 바뀌지 않는다(줌 중심 고정)
8. 검색 없이 진입 → 처음부터 핀 모드
9. "이 위치로 등록하기"가 두 모드 모두에서 올바른 좌표를 넘긴다
10. 상세 화면(`static`)과 등록 흐름이 그대로 동작한다

## 후속

- 마커가 화면 밖으로 나갔을 때 되돌아가는 버튼.
- 마커 모드에서 지도를 많이 움직인 뒤 "이 위치로 등록하기"를 누르면 화면에 안 보이는
  좌표로 넘어간다. 지금은 카드에 주소가 적혀 있어 확인은 되지만, 위 버튼이 생기면
  더 분명해진다.
